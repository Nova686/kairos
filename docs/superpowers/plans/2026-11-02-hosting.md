# Hosting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kairos runs for free on an Oracle Cloud « Always Free » VM over HTTPS on a DuckDNS subdomain, installable on the iPhone home screen, backed up daily, and redeployable with one command.

**Architecture:** One Docker Compose stack on the VM: the Nuxt app (Node 22 image built from the repository), PostgreSQL 17 with pgvector, Caddy for automatic HTTPS, a DuckDNS updater, and a backup container. Scheduled Nitro tasks (plans 2 to 4) run inside the app container. The PWA manifest and icons come from `@vite-pwa/nuxt`. A health endpoint lets CI and the deploy script verify a release.

**Tech Stack:** Docker, Docker Compose v2, `pgvector/pgvector:pg17`, `caddy:2`, `@vite-pwa/nuxt` 1.1, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-02-kairos-design.md` (objective 13, section 5 « Gratuit de bout en bout », « iPhone / Safari », section 7 « Hébergement », « Hébergement de repli »). Depends on plan 2; plans 3 and 4 only add environment variables listed here.

## Global Constraints

- Free only: Oracle Always Free shape (Ampere A1, up to 4 OCPU / 24 GB) or, as the fallback, the Always Free AMD micro shape (1 OCPU / 1 GB) with `KAIROS_PHOTO_RECOGNITION=off`; DuckDNS; Let's Encrypt through Caddy; GitHub free tier.
- The image builds and runs on both `linux/arm64` and `linux/amd64`.
- Secrets only in the server's `.env` (never committed) and GitHub repository secrets: `NUXT_SESSION_PASSWORD` (≥ 32 chars), `NUXT_DATABASE_URL`, `POSTGRES_PASSWORD`, `KAIROS_DOMAIN`, `DUCKDNS_SUBDOMAIN`, `DUCKDNS_TOKEN`, `EBAY_CLIENT_ID`, `EBAY_CLIENT_SECRET`, `POKEMONTCG_API_KEY`, `PSA_API_TOKEN`, `KAIROS_PHOTO_RECOGNITION`.
- Only ports 80 and 443 are open publicly (plus 22 for SSH); PostgreSQL is never exposed.
- The step-by-step guide is written in French for the author.

## Review Focus

- A fresh VM following the guide ends with a working HTTPS site: Oracle's Ubuntu images block ports 80/443 in `iptables` on top of the security list, and the guide must open both.
- The app container restarting (deploy, crash, VM reboot) does not lose data: database, models and OCR data live in named volumes.
- A failed deploy (health check red) leaves the previous containers serving.
- The backup actually restores: the restore procedure is exercised by a test, not only written.
- On the AMD micro fallback, the photo tab is hidden and the app stays within 1 GB of memory (no model loaded).

### Task 3: Compose stack, Caddy, DuckDNS and backups

**Files:**
- Create: `deploy/compose.yml`, `deploy/Caddyfile`, `deploy/env.example`, `deploy/backup/backup-database.sh`, `deploy/backup/restore-database.sh`
- Test: `tests/deploy/backup-restore.sh`, `.github/workflows/stack.yml`

**Interfaces:**
- Produces (`deploy/compose.yml`, project name `kairos`):
  - `app`: built from `..` (`Dockerfile`), `env_file: .env`, `NUXT_DATABASE_URL=postgres://kairos:${POSTGRES_PASSWORD}@database:5432/kairos`, volume `kairos-data:/app/.data`, `depends_on: database (service_healthy)`, `restart: unless-stopped`, no published port.
  - `database`: `pgvector/pgvector:pg17`, `POSTGRES_USER=kairos`, `POSTGRES_DB=kairos`, volume `kairos-database:/var/lib/postgresql/data`, healthcheck `pg_isready`, no published port.
  - `caddy`: `caddy:2`, ports `80:80`, `443:443`, `443:443/udp`, `Caddyfile` = `{$KAIROS_DOMAIN} { encode zstd gzip; reverse_proxy app:3000 }`, volumes `caddy-data`, `caddy-config`.
  - `duckdns`: `alpine:3` running a loop that calls `https://www.duckdns.org/update?domains=${DUCKDNS_SUBDOMAIN}&token=${DUCKDNS_TOKEN}&ip=` every 5 minutes (an in-container keep-alive of the DNS record, not an agent poll).
  - `backup`: `pgvector/pgvector:pg17` running `backup-database.sh` daily at 03:30 (sleep-until loop): `pg_dump -Fc` to `/backups/kairos-<YYYY-MM-DD>.dump`, keeps the 14 latest, volume `kairos-backups`.
  - `restore-database.sh <dump>`: stops `app`, restores with `pg_restore --clean --if-exists`, starts `app`.
- `tests/deploy/backup-restore.sh`: starts `database` + `backup` with a throwaway project name `kairos-backup-check`, inserts a row, runs a backup, drops the row, restores, asserts the row is back, tears the project down (`docker compose -p kairos-backup-check down -v`).

### Task 6: Installation guide and first deployment

**Files:**
- Create: `docs/hebergement/installer-kairos-sur-oracle.md`

**Interfaces:**
- Produces a French, numbered guide that ends with a working site:
  1. Create the Oracle Cloud account (card verification, no charge), region with ARM capacity (Paris or Marseille, else Frankfurt).
  2. Create the instance: Ubuntu 24.04, shape `VM.Standard.A1.Flex` 4 OCPU / 24 GB (fallback `VM.Standard.E2.1.Micro` and `KAIROS_PHOTO_RECOGNITION=off`), SSH key, public IP; security list ingress 80, 443 TCP and 443 UDP.
  3. On the VM: open 80/443 in `iptables` (`sudo iptables -I INPUT 6 -p tcp --dport 80 -j ACCEPT`, same for 443, then `sudo netfilter-persistent save`), install Docker Engine and the Compose plugin from Docker's apt repository, add the user to the `docker` group.
  4. DuckDNS: create the subdomain, copy the token.
  5. Clone the private repository with a read-only deploy key, copy `deploy/env.example` to `deploy/.env`, fill it (`openssl rand -base64 48` for the session password and the database password).
  6. `docker compose -f deploy/compose.yml up -d --build`, check `https://<sous-domaine>.duckdns.org/api/health`.
  7. `docker compose -f deploy/compose.yml exec app node .output/server/scripts/create-admin.mjs <email> <nom>` — **ruling for the builder:** plan 2's `create-admin` script must be bundled for production (Nitro `serverAssets` or a separate `tsx`-free build step); add whichever works and document the exact command here.
  8. iPhone: open the site in Safari, Share › « Sur l'écran d'accueil », allow the camera on first scan.
  9. Updates: `./deploy/deploy.sh` on the VM or the « Deploy » workflow; backups in the `kairos-backups` volume, restore with `deploy/backup/restore-database.sh`.
  10. Troubleshooting: certificate not issued (DNS not yet pointing, ports closed), ARM capacity unavailable (retry later or use the fallback), out of memory on the micro shape.
